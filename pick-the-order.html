Pick the order

The first thing you learn about distributed systems is that the order messages arrive in determines the state you end up with. It is the reason consensus protocols exist at all.

So: you choose the order.

Three thousand transactions, five nodes. Name any permutation you like — reversed, random, a different one per node. I will run it and publish the ledger hash.

It will be the same hash. It is always the same hash.

Why this is the interesting part

Ordering is normally something a system has to agree on: elect a leader to assign sequence numbers, or run a quorum round per operation, or stamp everything with a clock and hope the clocks are close. All of that exists because arrival order would otherwise decide the outcome.

If the final state is a function of the set of transactions rather than the order they showed up in, that whole problem stops applying. Nothing has to be agreed, because there is nothing left to disagree about.
